# Security policy

## Supported versions

Security fixes are provided for the current release line.

| Version | Supported |
| --- | --- |
| 0.5.x | Yes |
| Earlier versions | No |

## Reporting a vulnerability

Please do not open a public issue for a vulnerability, credential exposure, or
unsafe download source. Use the repository's **Security > Report a
vulnerability** form to send a private report.

Include the affected version, platform, reproduction steps, expected impact,
and any relevant logs with account names, paths, tokens, and depot keys removed.
Reports will be acknowledged after review. A fix and disclosure timeline will
be coordinated according to severity and reproducibility.

## Scope

Reports are especially useful for path traversal, unsafe archive extraction,
signature or checksum bypasses, unintended credential storage, insecure update
behavior, and operations that modify files without the documented preview,
confirmation, backup, or audit controls.
